# Claude·Codex 실제 토론 검증

2026-11-07 설치된 Claude Code 2.1.319와 codex-cli 0.163.0의 기존 구독 로그인을 사용했다. Claude는 `sonnet`(응답의 실제 모델 `claude-sonnet-5-5`), Codex는 모델 미지정 기본값이다. Codex 이벤트에 실제 모델 식별자가 없어 특정 모델 이름을 추정하지 않는다.

계좌·포지션·주문 없이 가상 종목 `SYNTH`의 동일한 합성 보고서 4개, 근거 ID 8개만 제공했다. 임시 작업 폴더와 별도 SQLite에서 실행했다. Claude는 `--tools ""`, restricted/safe mode, 빈 MCP 설정을 사용했고 Codex는 제품의 `run_turn` 경계를 그대로 사용했다. Codex 이벤트에 명령·도구 실행은 없었고 Claude의 검색·웹 조회 수는 0이었다. 출력은 제품의 `DebateTurn`과 `turn_error`로 검증했다. 실제 매매 세션 전체의 통합 검증이나 수익성 백테스트는 아니다.

| 턴 | Claude 강세 측 | Codex 약세 측 |
|---|---|---|
| 독립 의견 r0 | 자기 쟁점 4개, BULLISH, 확신 0.50 | 자기 쟁점 4개, BEARISH, 확신 0.60 |
| 상호 반론 r1 | 상대 쟁점 4/4 답변, 확신 0.48 | 상대 쟁점 4/4 답변, 확신 0.60 |
| 재답변 r2 | 상대 쟁점 4/4 반론 + 자기 쟁점 4/4 재답변, 확신 0.45 | 상대 쟁점 4/4 반론 + 자기 쟁점 4/4 재답변, 확신 0.60 |

Claude r2의 최초 출력에는 `replies`가 비어 있었다. 검증기는 이를 거부했고 체크포인트에 성공으로 저장하지 않았다. 누락된 자기 쟁점 ID를 오류 피드백으로 제공한 1회 재시도에서 통과했다. 따라서 성공 턴은 6개, CLI 실행 시도는 7회(Claude 4, Codex 3)다. 이 실패를 숨기거나 무조건 자동 재시도 성공으로 간주하지 않는다. 양쪽의 r2 재답변 누락·중복을 거부하는 합성 회귀 테스트도 추가했다.

## 내용 평가

- 양쪽이 독립 쟁점을 먼저 제시하고 모든 쟁점에 반론했다. 상대의 발언을 보고 최초 주제를 정하는 방식은 아니었다.
- 양쪽 모두 지연된 일간 관측과 실시간 자료, WTI 현물과 선물, 광의 달러지수와 DXY를 구분했다. 유가·달러·금리 상승을 일률적인 악재로 취급하지 않았다.
- Codex는 매출 성장 전망만으로 PER 30배를 적정하다고 판단할 수 없다는 점과 금리 변화의 원인·기업 노출이 미확인이라는 점을 지적했다. Claude는 일부 반론을 수용하고 확신을 낮췄지만, 이익·비교기업 자료가 없어도 잠정 `FAIR`를 유지했다. 형식 검증을 통과해도 근거의 충분성이 자동 보장되지는 않는다.
- Claude는 조건부 판단, Codex는 대기를 유지했다. 단일 합성 사례이고 강세/약세 역할이 고정돼 있어 공급자 자체의 우열이나 편향 감소 효과를 입증할 수 없다. 역할 교대와 다수 과거 사례 검증이 후속 과제다. 운영 Codex 기본 OFF는 유지한다.

## 소요·사용량

7회 시도의 합산 실행 시간은 167.626초였다. Codex가 보고한 입력/출력 토큰은 53,959/3,930이며 비용·구독 사용률은 미제공이다. Claude 4회 응답은 일반 입력 10, 캐시 생성 입력 31,100, 캐시 읽기 입력 19,024, 출력 11,640 토큰을 보고했다. CLI의 비용 추정 합계는 USD 0.2427224이며 구독의 추가 청구액을 뜻하지 않는다. 공급자별 캐시·시스템 입력 계산이 달라 토큰 수만으로 효율을 비교하지 않는다.

실행 로그·입출력 해시·모델 응답은 gitignore된 작업 자료에만 보존한다. 외부 기사 원문이나 인증값은 이 보고서에 포함하지 않는다.
