# M12 kernel/ops + 번들 + 전환 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 리플랫폼 마지막 마일스톤 — `kernel/ops`(health·retention·status·watchdog)를 넣어 `/system/health` 임시 판정을 교체하고, 옛 번들(PyInstaller·트레이·설치기·`build.yml`)을 이식하며, 남은 옛 테스트·이연 항목을 정리해 `FAKE_CLAUDE=1 trader daemon --dry-run` 하루 리허설과 `install` 교체를 사용자가 할 수 있게 만든다.

**Architecture:** 커널은 기능 이름을 모른다. health 는 `Feature.health_areas`(기능이 등록) + 커널 내장 영역 3개(jobs·llm·orders)를 러너가 순회하고 결과를 `control.ops_result` 에 둔다. status 는 `Feature.status_sections` + 커널 절 4개를 Markdown(`state/STATUS.md`)과 텔레그램 두 형식으로 그린다. retention·`ops_check` 는 커널 내장 잡. 번들은 옛 `packaging/` 을 경로만 맞춰 옮기고, 더블클릭 진입 `trader app` 은 **한 프로세스 안에서 데몬 스레드 + uvicorn 스레드**(웹 deps 는 `build_web_deps` 그대로 집행 포트 없음)로 묶는다. 이연 항목 중 "동작 보존" 범위(옛 저장소에 있던 기능·테스트)는 전부 이식하고, 순수 개선(계좌 단위 일시정지·fo 부가 필드·단타 상세·spot monitor 단타 제외)은 다음 Phase 로 넘긴다(스펙 §2.0 비목표: 의미 변경 없음).

**Tech Stack:** Python 3.12 · typer · APScheduler · FastAPI/uvicorn · pystray(런타임 추가) · Pillow·PyInstaller(build 그룹) · pytest. 프런트 변경은 작은 것 4건(SSE ping 수신 확인·뉴스 수집 버튼·지표 SSE 키·리스크 한도·승인 통화)뿐.

**Spec:** `docs/superpowers/specs/2026-11-02-kis-trading-agent-replatform-design.md` §2.1(`kernel/ops`·`kernel/platform` 줄), §2.6, §2.7, §2.7-1(리허설 자원 분리), §3 M12 행, 「검증」절 운영 리허설. 웹 쪽 고정 모양은 `docs/superpowers/specs/2026-11-04-m11-web-ui-design.md` §7(`GET /system/health` 응답)·§8.10(e)·「운영 이상 알림」(:153, :198). 옛 코드 원천은 `/Users/ohhyeonseok/LLM/trading-agent`(읽기 전용; `config/`·`state/`·`secrets/` 는 열지 않는다). 조사 노트(컨트롤러 스크래치, 참고용): `m12-survey/{ops,packaging,cli}.md`.

## Global Constraints

- **두 층·import 3층**: `kernel` 은 `features` 를 import 하지 않는다. 서비스 기능끼리·레인→서비스는 그 기능의 `api.py` 만. 레인(spot·fo·scalp)은 어떤 기능도 import 하지 않는다(필요한 것은 포트 주입). `tests/kernel/registry/test_import_boundary.py::test_real_tree_has_no_violations` 가 강제. `src/trader/__main__.py` 는 두 층 밖(검사 대상 아님).
- **기능 등록은 `features/<x>/feature.py` 의 `FEATURE` 한 곳**. health 영역·status 절·잡·큐 kind·SSE 키·설정 섹션 전부 거기서. 커널 내장 잡은 `kernel/daemon/builtin_jobs.py` 의 `BUILTIN_FEATURE`.

## 플랜 결정 (Ruling — 실행 중 바꾸지 않는다, 틀렸으면 PR 리뷰에서 되돌린다)

- **P1 health 영역 규약**: `HealthArea.check: (OpsContext) -> list[Item]`. 기능 영역은 **기능당 하나, key = feature id**(`spot`·`regime`·`ingest`·`fo`·`saveticker`·`evaluation`·`quotes`), 커널 내장 영역은 `jobs`·`llm`·`orders`. 항목 key 는 `"{area}.{세부}"`. 계약 검사가 영역 key 중복과 "기능 영역 key ≠ feature id" 를 막는다. 옛 `loss.*`→`regime.*`, `disclosure.*`→`ingest.*`, `orders.fill_ambiguous`/`reconcile.*`→`spot.*`, `llm.calibration_review`→`evaluation.calibration_review`.
- **P2 단계 어휘**: 내부는 옛 4단계(`ok·watch·warning·critical`) 유지. 웹 변환 `to_web`: critical→`fail`, warning→`warn`, watch→`info`(사유 목록에만, 머리 단계 미반영), ok 항목은 reasons 에 넣지 않는다. 웹 임시 판정의 "같은 kind 3연속 오류"·"세션 90%" 규칙은 옛 ops 규칙(`jobs.errors` 24h 건수, `llm.cap` 80%/100%)으로 대체한다.
- **P3 `/system/health` 원천**: 기본은 데몬이 적은 `control.ops_result`(`at` 이 `2 × ops_check 간격` 안이면). 없거나 오래됐거나 `?live=1` 이면 웹 프로세스가 직접 `check()` 를 돈다(웹은 포트 중 집행 포트가 없으므로 `orders.rate_limiter` 는 그 프로세스 리미터만 본다 — 옛과 같음).
- **P4 알림·쿨다운**: 데몬 `ops_check` 는 옛 `escalate`(상태 기반 dedup: 단계 악화 또는 새 warning+ 키) 그대로, 시간 쿨다운 없음. 외부 `watchdog` 은 옛 `RENOTIFY=1h` 그대로. M11 스펙이 "M12 에서 확정" 이라 한 값은 이 둘이다.
- **P5 retention**: 커널 내장 **cron 잡 `retention`**(`schedule.yaml` `retention: "17:20"` KST, misfire idempotent·catch_up direct). reflect 끝에서 부르지 않는다. 설정은 커널 `settings.yaml` 섹션 `ops: {retention_days: 120}`(30~3650). 보존 대상에 M11 테이블 `notices`·`control_log` 를 더한다(같은 cutoff). `PERSISTENT_PREFIXES = {"paused","watchlist","telegram_offset","memory_breaker"}`(옛 목록에서 `account_modes` 테이블로 옮겨 간 `mode`·`live_confirmed` 제거).
- **P6 status 두 형식**: `kernel/ops/status.py` 가 절 목록 `(title, lines)` 을 만들고, Markdown 은 `## title` 을 붙여 `state/STATUS.md` 로, 텔레그램 `/status`·웹 `/system/status` 는 지금처럼 줄만 잇는다. 커널 절은 Markdown 4개(운영 점검·데몬·마지막 실행·오늘 LLM 호출) + TODO 진행도·다음 할 일, 텔레그램은 앞 2개(운영 점검·데몬)만.
- **P7 `trader app`**: 한 프로세스. 데몬은 `Daemon.start(install_signals=False)` 를 `trader-daemon` 스레드에서, 웹은 `uvicorn.Server` 를 `trader-web` 스레드에서(`build_web_deps` 그대로 — 집행 포트 없음, M11 T3-R3 유지), 종료는 `server.should_exit=True` → `Daemon.shutdown(wait=True)`(실행 중 세션 대기) 순. 자식 프로세스 방식은 쓰지 않는다. 리허설의 포트 분리(`trader web --port 8788`)는 별도 명령이라 영향 없다.
- **P8 최상위 CLI 별칭**: 두지 않는다(M4 Ruling 과 일관). `trader evaluation …`·`trader spot …` 그대로. CLAUDE.md 명령표가 정본. (M8 A13 해소)

## Review Focus

1. **영역 하나의 예외가 점검 전체를 막지 않는다**: 기능 `check` 가 예외를 던지면 그 영역만 `"{area}.error"` warning 1건이고 나머지 영역·단계는 정상 계산 → Task 1 `test_check_isolates_failing_area`.
2. **데몬이 죽어 `ops_result` 가 없거나 오래됐을 때 `/system/health`**: 웹이 직접 판정해 `fail` + 「데몬이 꺼져 있어요」 를 내고, `checked_at` 은 지금 → Task 2 `test_health_live_when_cache_missing_or_stale`.
3. **retention 이 살아 있는 것을 지우지 않는다**: queued/running 요청·`agent_calls` 가 가리키는 세션 runs·영구 키·날짜 모양 계좌 id 의 `paused:`·오늘 플래그는 남고 2회차는 0 → Task 5 `test_prune_removes_only_old_items`.
4. **더블클릭 실행에서 데몬 잠금 실패(이미 떠 있음)**: 트레이·웹을 띄우지 않고 안내 + exit 1, Windows 콘솔이면 Enter 대기 → Task 11 `test_app_exits_1_when_daemon_fails_early`·`test_main_double_click_pauses_on_error_in_windows_console`.
5. **승인 집행 요청을 취소하면 선점이 풀려 다시 결정할 수 있다** → Task 16 `test_cancel_queued_approve_execute_releases_claim`.
