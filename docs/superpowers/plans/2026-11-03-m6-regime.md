# M6 features/regime + 의도 생산자 + scan 테마·사건 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 옛 `risk/{regime,killswitch,blackout}.py`·`orchestrator/{market_view,hedge,cash_park,rebalance}.py`·`tools.py` 의 market 절·`scan/{theme,events,membership}.py` 와 데몬의 해당 몫을 새 저장소로 이식해, 국면 판정·시장 세션(전략가 헤지 제안)·킬스위치·권리 블랙아웃이 현물 게이트에 들어가고, 헤지·현금 운용·주간 리밸런스 의도가 spot 안에서 생산되며, 테마 열기·사건 감지가 돌고 테마 안전장치가 게이트에 연결되게 한다.

**Architecture:** 서비스 기능 둘을 새로 만든다. **`features/regime`**(국면 3지표+히스테리시스·`regime:<m>` 플래그·킬스위치·권리 블랙아웃·시장 세션 `market` SessionKind 와 `trader tool market …` 도구·`{market}_regime`/`ksd_events` 잡·큐 kind `market_view`·`trader regime` CLI·`/kill`)과 **`features/scan`**(테마 열기 `theme_heat`·사건 감지 `events.yaml`·`membership`·`{market}_theme` 잡·`news.post_ingest` 훅·`trader scan` CLI). 둘은 커널과 `ingest.api`·`saveticker.api` 만 import 한다. **`features/spot`**(레인)은 두 기능을 import 하지 않고 `ports["regime"]`·`ports["scan"]` 로 국면·기울기·킬스위치·블랙아웃·헤지 설정·테마 소속을 받아 `rules.evaluate` 의 이미 있는 인자(`regime`·`agent_tilt`·`killswitch`·`trade_block`·`Portfolio.theme_of/hedge_tickers`)에 꽂고, 하위 의도 생산자 `hedge.py`·`cash_park.py`·`rebalance.py` 를 monitor 틱과 `{market}_rebalance` 잡에서 돈다. 시장 세션 도구가 쓰는 토론 스키마·요약·체크포인트 헬퍼는 spot 전용이 아니므로 **커널 `kernel/session/{schemas,debate,tooling}.py` 로 승격**하고 spot 은 재export 한다(스펙 §2.1 `kernel/session` 의 "스키마"). 모든 주문·취소는 M4·M5 와 같이 `kernel/execution/core` 를 지난다.

**Tech Stack:** Python 3.12, pydantic v2, SQLite(WAL), APScheduler, typer, pytest, pandas(이미 의존성 — `theme.mature` 종가표). 새 의존성 없음.

**Spec:** `docs/superpowers/specs/2026-11-02-kis-trading-agent-replatform-design.md` §2.1(`features/regime` L75·`features/spot` 의도 생산자 L74·`features/scan` L73), §2.2(Lane·`OrderIntent` origin 표), §2.3(ports·hooks·queue_kinds·settings_sections 의 `excluded_tickers`), §2.7-1(import 3층), §3 M6 행(L221). 인벤토리(세션 산출물, 저장소 밖): 옛 모듈·테스트 명단은 각 Task 의 「옛 출처」에 옮겨 적었다.

## Review Focus

스펙이 암시하지만 옛 테스트가 덮지 않는 입력. 각 줄의 테스트는 해당 Task 에 있다.

1. `regime:<m>` 플래그가 없거나 `hedge.enabled=false` 면 게이트는 `bull`·기울기 0·킬스위치 없음으로 동작하고 헤지 틱은 `{"skipped": …}` 로 조용히 끝난다(포트가 없을 때도 주문 경로가 멈추지 않음). → Task 4·7
2. 킬스위치가 자동 발동한 틱에서 신규 BUY/ADD 는 거부되고 그 계좌의 미체결 BUY 는 회수되지만 **헤지 ETF 보유·헤지 매수는 유지**되며(`keep=hedge_tickers`), 승인 대기 BUY 는 승인 실행 재판정에서 거부된다. → Task 4
3. 시장 세션이 상한·실패로 `view=None` 이어도 `{market}_regime` 잡은 국면 갱신을 마치고 `reapply` 를 건너뛰며 직전 `regime:<m>` 를 유지한다(세션 실패가 국면을 지우지 않음). → Task 6
4. `news.post_ingest` 훅의 사건 감지가 예외를 내도 `news_collect` 결과는 `hooks` 항목에 오류만 남고 수집은 성공으로 끝나며, 같은 사건 알림은 시장·운영일당 1회다. → Task 11
5. `{market}_rebalance` 잡과 큐 kind `rebalance` 는 `paused` 면 완료 플래그를 쓰지 않고 skip 하고, 리밸런스 ADD 는 손절선 이상 가격에서만 나가며 `excluded_tickers`(헤지·현금 운용) 종목은 레그에서 빠진다. → Task 9
