# M7 features/ml + scan 확장(정량·스크리너·발굴·트리거) + spot scan_analyze Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 옛 `ml/{features,dataset,walkforward,registry,train,tune,ranker,quant_report,universe_pit}.py`·`ml/models/quant.py`, `scan/{quant,screener,discovery,universe_check,sector_suggest,backtest}.py`, 데몬의 `_scan_body`·`_analyze_body`·`_scan_analyze_body`·`_discover_body`·`_news_trigger`·`_disclosure_trigger`·`_universe_members_body`·`_ml_train_body`·`_features_action`·부트스트랩 백필, 텔레그램 `/run`·`/watch`, 세션 kind `screen`·`discover`(scout·screener)를 새 저장소로 이식해, 피처 스토어 → 퀀트 모델 학습·승격 → 정량 필터+ML 랭킹 → scout 발굴 → screener 선정 → 종목 분석(`05_quant` 포함)이 `{market}_scan_analyze` 잡 하나로 이어지고, 장중 뉴스·중요 공시가 재분석·발굴 세션을 큐에 넣게 한다.

**Architecture:** 서비스 기능 **`features/ml`** 을 새로 만든다(피처 스토어 parquet·데이터셋·워크포워드·`QuantModel`·레지스트리·학습/튠·퀀트 리포트·시점 유니버스 `universe_members` v12·`ml_train`/`universe_members` 잡·큐 kind `features_backfill|features_snapshot|features_derive|ml_train`·`daemon.bootstrap` 훅·`trader ml …` CLI·`ports["ml"]`). **`features/scan`** 을 확장한다(정량 필터 `quant`·ML 랭커 `ranker`(ml.api 소비)·스크린 백테스트·유니버스 점검·섹터 제안·관심종목 `/watch`·발굴 `discovery`·스크리너 `screener`·세션 kind `screen`/`discover`와 에이전트 `scout`·`screener`·`scan-orchestrator`·도구 `tool scan discovery-inputs|submit-discovery|submit-screen`·큐 kind `discover`·`news.post_ingest` 훅의 뉴스/공시 트리거·`ports["scan"].run_scan/sector_of`). **`features/spot`**(레인)은 `{market}_scan_analyze` 잡·큐 kind `scan_analyze`/`analyze_ticker` 를 소유하고 scan 은 `ports["scan"]`, ml 은 `ports["ml"]` 로만 받는다(`05_quant`·`trader_context["quant"]`·유니버스 밖 발굴 종목 스냅샷·섹터 상한 `sector_of`). 작업 대기열은 M5 커널 그대로이고(**`features/jobs` 패키지 없음**) M7 은 QueueKind·텔레그램 `/run`(커널 내장)·`/watch`(scan)만 더한다. RL 사이저는 메모리·성과(M8)에 의존하므로 **M8 로 이연**한다. 스펙 §2.1 표가 `ml/universe_pit.py` 를 scan 에 두었지만 학습(`train._apply_pit`)이 소비하므로 **ml 이 소유**하고 scan 백테스트는 `ml.api` 로 쓴다.

**Tech Stack:** Python 3.12, pydantic v2, SQLite(WAL), APScheduler, typer, pytest, pandas, **새 의존성 `scikit-learn`·`joblib`·`pyarrow`·`numpy`(명시)**, 선택 extra `lightgbm`(Windows 휠 있음).

**Spec:** `docs/superpowers/specs/2026-11-02-kis-trading-agent-replatform-design.md` §2.1(`features/scan` L73·`features/ml` L78·`features/jobs` L82), §2.3(ports·hooks·queue_kinds·session_kinds·tools), §2.7-1(import 3층), §3 M7 행(L222). 인벤토리(세션 산출물, 저장소 밖 `m7-inv-{ml,scan,daemon,rl,newrepo}.md`): 옛 함수 시그니처·상수·테스트 단언은 각 Task 의 「옛 출처」에 옮겨 적었다.

## Global Constraints

- **동작 보존.** 옛 테스트의 단언을 바꾸지 않는다(import 경로·fixture·생성자·설정 객체·CLI 경로만). 바꿔야 하는 단언은 「바꾸는 옛 단언」 표의 것만(없으면 표에 추가하고 PR 본문에 적는다). 옛 코드의 결함(`_features_dir` 가 읽기 경로에서 mkdir, `registry.promote` 가 다른 버전을 내리지 않음, `discovery.merge` 와 `resolve` 의 `max_event` 기본값 불일치(8 vs 0), `_discovery_inputs` 의 `schema_version` 1 고정, `registry.demote/promote` 의 벽시계, `_news_trigger` 가 게이트 전에 `news_trigger_at` 갱신)은 고치지 않고 README 「알려진 차이」에 적는다.
- import 3층: `kernel` 은 `trader.features` 를 import 하지 않는다. **`features/spot` 은 `trader.kernel.*` 만**(지연 import 포함 금지) — scan 결과·섹터는 `ports["scan"]`, 퀀트·피처는 `ports["ml"]`, 수집은 `ports["inputs"]`, 계좌·시세는 `ports["accounts"]`. `ml` 은 커널 + `ingest.api`·`regime.api` 만, `scan` 은 커널 + `ingest.api`·`saveticker.api`·`regime.api`·`ml.api` 만(**ml 은 scan 을 import 하지 않는다** — 랭커가 scan 에 있는 이유). `tests/kernel/registry/test_import_boundary.py::test_real_tree_has_no_violations`·`test_contracts.py` 가 강제한다. 테스트 코드는 어느 기능이든 import 할 수 있다(`tests` 는 패키지: `from tests.features.ingest.helpers import FakeMarket, FakeDart, FakeEdgar, make_candles, T0`).
- **커널 수정은 Task 1·2 가 명시한 것만**: `kernel/execution/ports.py` 의 `MlPort` Protocol·`ScanPort` 확장, `kernel/session/schemas.py` 의 `QuantReport`, `kernel/execution/ledger.py` 로 `insert_trigger`·`decision_id`·`latest_decision`·`exchange_of` 승격, `kernel/execution/horizon.py`(spot `horizon.py` 승격), `kernel/ledger/names.py`(spot `labels.py` 승격), `kernel/daemon/queue_jobs.enqueue_from_job(..., priority=None)`, `kernel/notify/commands.py` 내장 `/run`. 그 뒤 Task 에서 커널을 고쳐야 하면 ledger 에 Ruling 으로 적고 최소로.
- **LLM 은 도구만**: screen·discover 세션은 `tool scan discovery-inputs`·`tool submit-discovery`·`tool submit-screen` 만 쓴다(`--allowedTools` 는 커널 `tool_command()`). 코드 확정·거래소·제외·병합은 파이썬(`discovery.resolve/merge`). `05_quant` 는 파이썬이 쓴다(LLM 쓰기 불가 — spot `WRITE_RULES` 에 넣지 않는다).
