# M9 features/scalp Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 옛 `trading-agent` 의 분 단위 단타 레인(`scalp/engine.py`·`signals.py`, 판정자 `scalp-judge`, 데몬 잡 `kr_scalp`/`us_scalp`, CLI `trader scalp`)을 새 저장소의 레인 기능 `features/scalp` 로 이식하고, 그 과정에서 드러난 커널·spot 갭(레인 간 주문 경로·`/status` 절 격리·`_kind` 접미사)과 TODO 의 M9 이연을 함께 닫는다.

**Architecture:** scalp 는 `tier="lane"` 기능이다. 어떤 기능도 import 하지 않고 포트 4개(`accounts`·`regime`·`scan`·**`stock_exec`**)만 쓴다. `stock_exec` 는 spot 이 새로 노출하는 포트(커널 `StockExecPort` Protocol)로, 현물 주문 집행(게이트 `is_scalp` 면제·승인·멱등·기록)·주문 취소·체결 동기화를 레인 밖에 제공한다 — 옛 `executor.execute(scalp_leg=…)` 호출과 1:1 대응. 포지션 상태는 옛 그대로 JSON 파일(`state/scalp/<date>/<market>.json`·`events.jsonl`)이라 **새 원장 마이그레이션은 없다**. 판정자는 커널 `session/quick.ask_json` 단발 호출(haiku, 도구 없음)이고, 스레드 풀 `ScalpJudge` 는 데몬 수명 동안 하나(모듈 단일체 + `JobSpec.teardown`).

**Tech Stack:** Python 3.12, pydantic v2, sqlite3, APScheduler(커널 데몬), typer, pytest. 새 의존성 없음.

**Spec:** `docs/superpowers/specs/2026-11-02-kis-trading-agent-replatform-design.md` §2.1(`features/scalp` 행), §2.2(Lane 추상·공유 타입), §2.3(레지스트리 계약), §2.7-1(import 3층), §3 M9. 옛 코드 인벤토리(세션 한정 scratchpad): `m9-inv-scalp-core.md`·`m9-inv-scalp-xref.md`·`m9-inv-newrepo.md` — 구현자는 옛 저장소 `/Users/ohhyeonseok/LLM/trading-agent/src/trader/scalp/*`·`tests/scalp/*`·`tests/test_daemon_scalp.py` 를 직접 읽어 이식한다(`config/`·`secrets/`·`state/` 는 읽지 않는다).

## Global Constraints

- 3층 import 규칙: `kernel` ← 서비스 기능 ← 레인(spot·**scalp**). **scalp 는 `trader.kernel.*` 와 자기 패키지만 import 한다**(`trader.features.spot`·`regime`·`scan`·`accounts`·`ingest` 등 어떤 기능도 금지; 필요한 것은 `ctx.ports`/`deps.ports` 의 `accounts`·`regime`·`scan`·`stock_exec`). `tests/kernel/registry/test_import_boundary.py::test_real_tree_has_no_violations` 가 강제한다. 테스트 코드는 이 규칙에 묶이지 않는다(spot 포트 구현체를 직접 조립해도 된다).
- 주문·취소는 `features/**` 에서 `.place_order(`/`.cancel_order(` 를 부르지 않는다(`tests/kernel/registry/test_order_paths.py`). scalp 의 모든 주문은 `ports["stock_exec"].execute(...)`, 취소는 `ports["stock_exec"].cancel(...)`, 체결 동기화는 `ports["stock_exec"].sync_fills(...)` 로만.
- `scalp` origin 의 `OriginSpec` 은 **spot 의 `ORIGINS` 에 그대로 둔다**(spot executor 가 `47_scalp_<leg>`/`57_order_scalp_<leg>` 단계·`|q{qty}` 멱등 꼬리·`is_scalp` 면제를 구현하므로). scalp `Feature.origins=()`. `tests/features/spot/test_executor.py::test_origin_table_matches_flags` 의 origin 집합 단언은 바뀌지 않는다.
- 원장 마이그레이션 추가 없음(다음 번호 14 는 M10 에 남긴다). 상태 파일은 `state/scalp/<YYYY-MM-DD>/<market>.json`·`events.jsonl`(옛 스키마 그대로: `open/closed/done/halted/pending/outbox/digest_at/carried`).

## Review Focus

1. **분봉·시세 조회가 한 종목에서 예외**를 내도 다른 후보 평가와 열린 포지션의 청산 점검은 그 틱에서 계속되고, 결과에 `errors` 로 남는다 — Task 5 `test_minute_fetch_failure_isolated_per_ticker`.
2. **일시정지 중** 열린 포지션은 손절 조건이어도 주문·취소를 내지 않고 `closing` 으로 기다리며, 해제 뒤 첫 틱에 청산된다 — Task 6 `test_paused_does_not_drop_open_position`(옛 테스트 이식).
3. **실전 계좌(`env != "paper"`)는 모드가 `auto` 여도 어떤 다리도 만들지 않는다**(모의 전용) — Task 5 `test_tick_enters_on_signal_paper_only_and_once_per_ticker`(옛) + `test_real_account_never_gets_scalp_legs`.
4. **판정자 하루 상한·사용량 감속**에 걸리면 진입하지 않고 이벤트(`judge`, `verdict: None`)만 남긴다 — Task 5 `test_ask_returns_none_when_cap_reached_or_throttled` + `test_judge_throttled_is_event_not_entry`.
5. **데몬 종료 중**(`stop_event` set) 판정 요청은 `None` 을 돌려주고, 잡 `teardown` 이 스레드 풀을 닫는다(미회수 future 취소) — Task 7 `test_judge_teardown_shuts_pool_and_stop_event_short_circuits`.

## Ruling(플랜 단계 결정 — 실행 중 틀린 것이 드러나면 장부에 적고 되돌린다)

- **A1 주문 경로**: spot 이 포트 `stock_exec`(커널 `kernel/execution/ports.py::StockExecPort` Protocol: `execute`·`cancel`·`sync_fills`)를 노출하고 scalp 는 그것만 쓴다. 대안(scalp 자체 게이트 + `core.transmit`)은 `rules.evaluate` 의 비중·현금·종목수·섹터·킬스위치·bear 규칙을 복제하게 되어 기각. 비용: 레인(spot)이 포트 공급자가 되는 선례 1개 — README·architecture.md 에 "현물 집행 서비스" 로 명시.
- **A2 origin**: `scalp` OriginSpec 은 spot 소유 유지(위 Global Constraints). `contracts.check` 의 origin 중복 검사와 충돌하지 않는다.
- **A3 상태**: JSON 상태 파일 유지, 마이그레이션 없음. legs 없는 옛 상태(`assumed` 변환) 코드는 유지하되 테스트 `test_legacy_state_without_legs_sells_once_with_cap` 는 이식하지 않는다(새 저장소에 옛 파일이 없다).
- **A4 스케줄**: 잡 `JobSpec(id="{market}_scalp", kind="scalp", trigger="interval", per_market=True, schedule_key="{market}.monitor.interval_s", interval_s=60, enabled=None, gate="none", heavy=False, misfire="default", catch_up="none", start_soon_s=30, body=scalp_job, teardown=judge_teardown)`. **게이트는 `none`** — 옛 `_scalp_job` 처럼 창 밖·주말·휴장·일시정지에서도 본문이 돌아 `{"skipped": …}` 를 돌려주며 그날 모인 outbox 를 flush 해야 하므로(게이트 `monitor` 는 본문을 아예 부르지 않는다). 본문이 커널 `market_hours`·`ports["accounts"].holiday_fn()`·`paused` 로 직접 거른다. 옛 `SCALP_INTERVAL_S=60` 상수 → 감시 주기 키 재사용(단타 전용 주기는 두지 않음; README). `enabled=None` 이라 잡은 항상 등록되고 본문이 `scalp.enabled` 를 본다(옛과 같음).
- **A5 판정자**: `AgentDef("scalp-judge", agents/scalp-judge.md, ScalpVerdict)` 를 `Feature.agents` 에 등록, `quick.ask_json(settings, conn, agent=AGENT, payload=, schema=, cap=cfg.judge_daily_cap, timeout_s=cfg.judge_timeout_s, now=, cancel=stop_event, fake=lambda: FAKE_VERDICT|FAKE_ADVICE)`. `agent_calls.agent='scalp_judge'`. 호출 전 `usage.session_allowance(conn, settings, kind="scalp_judge", now=)` 가 거절하면 `None`(판정 없음) — 옛엔 없던 감속 연동(briefing 선례). `settings.models.scalp_judge` 는 선택(없으면 md `haiku`).
- **A6 후보 소스**: `_scan` 체크포인트(커널 `run_store.read_checkpoint(market_dir(today, market, state), "_scan")` 의 `picks[].ticker`·`analyze_targets[]{ticker,exchange}`), 뉴스 트리거(커널 테이블 `job_requests WHERE source='news' AND kind='analyze_ticker' AND requested_at >= ? AND < ?`(`day_bounds`)), 관심종목은 **`ScanPort.watchlist(conn, market) -> list[str]`** 를 새로 더해 받는다(scan `watchlist.get_watchlist` 위임). 제외: 보유(`ports["accounts"].brokers()` 의 `get_positions(market)`), 헤지 종목(`ports["regime"].hedge_tickers(market)`), 오늘 `done`, 현재 `open`.
- **A7 허용 판정(`allowed`)**: 옛 순서 그대로 — `scalp.enabled` → 모의 계좌 존재(`env=="paper" and market in markets`) → `ports["accounts"].paused(conn)` → `halted` → (`regime.hedge_cfg().enabled` 일 때만) `regime.state(conn, market)=="bear"` → `regime.view_today(conn, market, today)` 의 `scalp_ok is False` 또는 `stance=="RISK_OFF"`(둘 다 `confidence >= hedge_cfg().agent_min_confidence` 일 때만) → `max_positions`. 킬스위치는 게이트(stock_exec 안)가 본다.
