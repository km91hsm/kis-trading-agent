# 운영 화면 사용성 보완

사용자 피드백: Codex 사용량 누락, 페이지 이동 후 스크롤 유지, 양 테마의 흐린 상태 표식, 잡 큐 정렬, 쓰기 토큰 입력의 중복감과 숨기기.

## 범위와 검증

1. Claude·Codex 사용량을 공급자별로 표시한다. Codex는 공식 읽기 RPC만 사용하며 모델 턴을 시작하지 않는다. 구독 사용률과 프로그램 내 호출 집계는 분리하고, 미제공·오류·이전 관측을 0%로 바꾸지 않는다. 시간 제한·출력 상한·프로세스 정리·캐시·동시 조회를 검증한다.
2. 공통 페이지 번호를 바꾸면 새 목록의 시작으로 스크롤과 키보드 포커스를 옮긴다. 첫 화면 로딩·자동 갱신·현재 페이지 재클릭은 화면을 움직이지 않는다. 한 화면의 여러 목록을 구분한다.
3. 라이트·다크 전체 화면의 상태 표식, 보조 문구, 표, 버튼, 입력과 상호작용 상태를 점검한다. 회색 표식에는 전용 색·배경·테두리를 사용한다. 재현되지 않은 사용자 환경의 현상을 확인된 CSS 충돌로 주장하지 않는다.
4. 잡 큐는 진행 우선/최신 요청순과 상태 필터를 제공하고, 대기 요청은 실제 큐의 우선순위·등록 순서에 맞춘다. 화면의 표시순과 스케줄러 집행은 구분하며 실행·취소 확인을 유지한다. 레인별 버튼을 안정된 순서와 폭으로 배치한다.
5. 쓰기 토큰은 저장 후 접고 언제든 열거나 숨길 수 있게 한다. 저장 개수와 교체 의미를 설명하고 값은 표시하지 않는다. 저장 성공 시 이전 인증 안내를 닫고, 저장 실패 때 입력·오류를 유지한다.

## 전달 절차

- 독립 작업은 사용량·잡 큐·가독성 진단으로 나누고 공통 페이지 이동과 토큰은 통합 담당자가 수정한다.
- 기능 회귀는 실패를 재현한 뒤 수정한다. 공통 웹 전체 테스트·타입 검사·빌드, Python 관련 테스트·전체 CI를 확인한다.
- 합성 화면으로 데스크톱·모바일, 양 테마·긴 문자열·오류 상태·포커스와 페이지 이동을 점검한다.
- 독립 코드 리뷰와 CI 이후 PR을 머지하고 기존 승인 범위대로 운영을 반영·재시작한다. 실행 중 작업을 확인하고 원장·설정·웹을 백업한다.
- 계좌 모드·매매 전략·Codex 토론 토글·실제 토큰 값은 변경하지 않는다. 실제 주문·모델 호출을 검증 수단으로 사용하지 않는다.
