# 인증·작업 상태·AI 토론 안정성 보완

사용자가 승인한 네 가지 보완을 적용한다. 메뉴·디자인을 다시 만드는 대신, 실제 사용에서 드러난 인증 안내·현재/과거 오류 구분·리스크 명칭·토론 실패를 기존 구조 안에서 해결한다.

## 접근과 범위

- 인증을 자동으로 우회하거나 원격 브라우저에 자격 증명을 전송하지 않는다. 기존 WEB_TOKEN·같은 출처·직접 로컬 제한은 유지하고, 화면은 **설정 변경 인증**이라는 이름과 조작 전 안내를 제공한다. 로컬/원격 주소별 저장 차이, 저장된 키와 서버가 허용한 인증의 차이를 설명한다. 403의 로컬 접속 제한을 토큰 없음으로 오인하지 않는다.
- 리스크 선택에 **리스크 ON — 제한적 매수**, **리스크 OFF — 신규 매수 차단**, **자동 — 시장 판단 따르기**를 사용한다. 일반 현물 적용 범위, 종목당 10%·최대 2종목과 더 작은 기존 한도, 단타·파생 별도 제어를 명시한다. 실제 정책 값·POST 계약·실전 확인 강도는 바꾸지 않는다.
- 자동 작업에서 종료 요청에 따른 중단·최근 실패·후속 정상 실행을 구분한다. 기존 원장의 status/error를 바꾸지 않고 조회용 메타데이터를 계산한다. 같은 시장·종목·계좌/요청 인자 범위가 확인될 때만 후속 정상 실행을 연결하며, 다른 범위의 성공이나 skipped를 복구 증거로 쓰지 않는다. 후속 정상 실행이 근본 원인 해결을 보장한다고 표현하지 않는다. 과거 오류를 숨기지 않는다.
- AI 토론은 현재 정규화·검증·Claude 대체 재실행을 먼저 확인한다. 관측된 근거 ID 오류/ValueError를 합성 입력으로 재현하고, 이미 고쳐진 것은 회귀 검사로 입증한다. 확인된 결함만 수정하며 존재하지 않는 근거를 만들거나 검증을 완화하지 않는다. 공급자 원문·자격 증명을 오류 기록에 노출하지 않는다. 실제 AI 호출·실제 작업 재실행은 하지 않는다.

## 선택

기존 React/Python 화면과 조회 API의 작은 확장을 선택한다. 별도 인증 체계·원장 상태 재작성·무제한 자동 재시도는 범위를 벗어나고 기존 안전 계약을 바꾸므로 도입하지 않는다. 기존 제한을 유지하는 구현 선택과 실패가 재현되지 않을 때의 추가 검증은 구현자가 판단한다.

## 검증 및 완료

각 동작을 RED→GREEN으로 확인한다. 최종 웹·Python·생성 파일·독립 규칙/요구사항 검토·PR CI를 거친다. 전체 pytest는 동시에 한 개만 실행한다. 사용자 승인 범위의 일반 UI/세션 안정성 PR은 검증 뒤 머지하며, 실제 주문 허용/집행 경로를 바꿔야 한다면 그 변경은 별도 검토한다. 운영 설정과 secrets/state는 직접 수정하지 않는다. 배포에는 이전에 승인된 앱 교체·정상 재시작 방식과 백업·설정 보존 검증을 적용한다.
