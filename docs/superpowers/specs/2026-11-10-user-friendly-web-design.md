# 사용자 중심 웹 UI와 현물 매수 정책

사용자는 대화에서 전체 메뉴·기능 위치·화면 흐름·디자인·모바일·리스크 조작을 포함한 변경 범위를 확인하고 구현을 승인했다. 세부 구현은 기존 React/CSS와 기능 포트를 활용한다.

## 목표와 화면 구성

- 첫 화면은 현재 시장별 매수 제한과 이유 → 확인할 문제·승인 → 판단·주문 집계 → 상세 기록 순서로 구성한다.
- 메뉴는 기존 URL을 보존하면서 오늘, 계좌·보유, 성과, 시장 데이터, 설정·운영으로 이해하기 쉽게 정리한다. 시스템 하위는 운영 상태, 자동 작업, 매매 정책, 연결·설정 등 목적을 드러낸다.
- 국면 절은 시장 상태·AI 판단·확신도·정량 지표·실효 매수 정책·수동 조작·이력을 모은다. 수집 세부 기록은 요약 뒤 펼쳐 보인다.
- 일반 종목 판단과 인버스 헤지를 구분한다. 작업 완료와 주문 허용 상태, 설정값과 실효 상태를 구분한다.
- 계좌·성과·데이터·설정 화면에도 목적 설명과 다음 행동 연결, 일관된 제목·여백·오류·빈 상태를 적용한다.
- Pretendard와 기존 아이콘을 사용하고 의존성을 추가하지 않는다. 본문 16px, 보조 14px, 최소 44px 조작 영역, 일관된 대비·포커스·최대 콘텐츠 폭을 사용한다. 밝은/어두운 테마와 375/768/1024/1440px를 검증한다.

## 현물 매수 정책

- 시장별 AUTO / RISK_ON / RISK_OFF. 기본 AUTO는 기존 동작과 동일하다.
- 수동 정책은 해당 시장의 운영일에만 유효하며 다음 운영일에는 자동 복귀한다. 사유·변경자·변경 시각·만료를 기록한다.
- 수동 RISK_ON은 일반 현물 신규·추가 매수를 종목당 최대 10%, 최대 2종목 범위에서 허용한다. 기존 한도가 더 작으면 그 한도를 따른다.
- 수동 RISK_OFF는 일반 현물 신규·추가 매수를 차단한다. 위험 청산·헤지·현금 운용·단타·파생에 자동 확장하지 않는다.
- AI 판단·확신도와 정량 국면은 원본 그대로 보존한다. 수동 정책을 AI 확신도 1.0으로 변조하지 않는다.
- 분석 입력·실제 위험 검사·승인 재검사는 같은 실효 정책을 읽는다. 과거 HOLD를 저장만으로 재실행하지 않는다.
- 웹 쓰기는 원장 control과 조작 이력만 변경한다. 주문·알림·유료 AI 호출을 직접 실행하지 않는다. 계좌 모드·LIVE 확인·일시정지·킬스위치·일일손실 등 기존 제한을 유지한다.
- 모든 쓰기는 기존 WRITE 인증. 영향을 받는 실전 현물 계좌마다 기존 require_confirm을 적용한다. 복수 계좌는 confirmations 사전으로 계좌별 입력을 확인한다.

## 공용 API 계약

`GET /settings/risk-policy` → `{markets: RiskMarket[]}`.

RiskMarket: `market`, `regime`(bull/neutral/bear/null), `asof`, `signals`, `values`, `streak`, `exit_streak_days`, `ai_view`(원본 판단/확신도/사유/일자 또는 null), `policy`(`mode`, `source`, `reason`, `expires_at`, `date`), `effective`(`stance`, `entry`: blocked/limited/standard/unknown, `reason`, `max_position_pct`, `max_positions`), `accounts`([{id,env}]), `history`([{at,mode,reason,actor,expires_at}]).

`PATCH /settings/risk-policy/{market}` body: `{mode: AUTO|RISK_ON|RISK_OFF, reason: string, confirmations?: Record<string,string>}`. 응답은 같은 전체 조회 형태. 사유 필수(공백 거부), 비운영 시장·잘못된 값·누락된 실전 확인 거부. control SSE를 사용한다.

## 대안과 선택

표시만 보완하는 안은 수동 조작 요청을 충족하지 않는다. AI 원본 덮어쓰기는 판단·헤지·파생에 영향을 섞으므로 독립 운용 정책으로 구현한다. 전체 재작성 대신 기존 라우트·내비 생성기·컴포넌트를 개선한다.

## 검증과 완료 조건

TDD로 정책 만료·시장 분리·확인·분석/집행 일치·승인 재검사와 UI 조작을 검증한다. 전체 Python 검사는 한 번에 하나만 실행한다. ruff, pytest, 웹 typecheck·Vitest·build 및 실제 개발 화면의 브라우저 확인을 통과하고 PR을 만든다. 주문 경로 변경이 있으므로 머지는 변경 요약 후 사용자 확인 대상이다. 운영 앱 설정은 변경하지 않는다.
