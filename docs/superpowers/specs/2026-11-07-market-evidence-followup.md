# 시장 자료 검증과 운영 반영 후속 설계

사용자는 KIS 실제 시세 확인, 입력 축약 개선, Claude·Codex 실제 토론 비교, 정확 DXY/WTI 공급 검토, 운영 업데이트·재시작을 순서대로 모두 진행하도록 지시했다. 계좌 모드 변경·시험 주문·신규 유료 데이터 계약은 포함하지 않는다. 기존 [시장 자료와 토론 안내](../../market-data-codex.md)의 출처·시각·결측 계약을 유지한다.

1. KIS 검증은 기존 인증·공유 rate limit을 통한 시세 GET만 사용한다. 자격증명·계좌번호는 출력하지 않고 주문 API는 차단한다. 운영 원장 대신 격리 저장소를 쓴다. KR/US 순위, SPX/COMP, 거래대금 단위와 누적 시점의 근거를 기록한다. 현재 휴장시간의 같은 값을 장중 증가율 검증으로 인정하지 않는다. 단위·시간을 확정하지 못하면 unknown을 유지한다.
2. 공통 토론의 기본 8000 UTF-8 bytes 상한은 유지한다. 블로그 최신 5건은 각 원문 발췌를 먼저 줄여 가능한 한 모두 보존하고 URL·source·posted_at·received_at을 바꾸지 않는다. 기본 발췌는 240→140→64자 순으로 줄이고 제목은 최대160자다. 자료가 너무 많거나 식별자만으로 상한을 넘으면 일부 생략과 실제 전달 coverage를 정확히 표시한다. 발췌는 LLM이 생성한 요약으로 표시하지 않는다. 뉴스/매크로/활동 자료의 결측·출처 보존도 회귀 검사한다.
3. 실제 토론 비교는 별도 임시 cwd/원장, 공개 또는 합성 동일 자료, 도구 미허용, 주문 연결 없이 기존 CLI 로그인을 사용한다. 최초 실호출은 양 모델 독립 의견·상호 반론·재답변 각1회(총6회)를 상한으로 한다. 실패 시 원인을 고치고 필요한 실패 턴만 최대1회 재시도한다. 공급자·버전·자료 해시·시간·출력·검증 결과를 비공개 작업 자료로 남긴다. 이것은 수익성 증명이 아니다.
4. DXY와 WTI 선물은 기존 공식 조사 결과를 재사용한다. 실제 공급 권한·비용이 확인되지 않으면 가입이나 활성화를 하지 않고 대체지표 및 부족 조건을 표시한다. KIS 코드 존재를 수집 성공으로 기록하지 않는다.
5. 전체 검증·리뷰·CI·머지 후 운영 적용한다. 실행 중 작업·대기 주문·설정을 먼저 확인하고, 서비스 정상 종료·새 백업·코드/웹/블로그 설정 반영·정식 원장 마이그레이션·재시작·읽기 상태 확인 순서를 따른다. 계좌 모드와 Codex 토글은 기존 상태를 유지한다. 기존 운영 프로세스 아래에서 소스만 바꾸지 않는다. 오류 시 서비스 실행 전 코드/설정/원장을 일관된 백업으로 복구한다.

실제 장중 5분 거래대금 이력과 시점별 백테스트 자료가 없는 동안 해당 성능 검증은 미완료로 남긴다. 자동 수집이 가동된 뒤 관측 이력으로 확인하며 과거 이력을 합성해 실측이라고 보고하지 않는다.
