# 상세 화면과 이동 흐름 보완

사용자가 전체 UI 검토의 세 가지 기능 문제와 여덟 가지 구조 개선을 승인했다. 기존 다섯 주 메뉴와 주소를 유지하고 상세를 필요한 맥락에서 보여 준다.

- 복수 시장 계좌에 시장 선택을 추가하고 위험·자산 추이를 같은 시장으로 조회한다. 보유 종목에도 시장·통화를 명시한다.
- 성과의 계좌·시장·기간은 주소에 저장한다. 새로고침·다른 화면 방문·뒤로가기에서도 유지하고 잘못된 계좌·시장·기간은 유효한 기본값으로 보정한다.
- 직접 접속한 절은 비동기 콘텐츠가 들어온 뒤에도 올바르게 보이고, 접힌 상세 안의 절은 펼쳐진다. 사용자가 스크롤·클릭하면 자동 위치 조정을 멈춘다.
- 파생은 별도 주 메뉴를 만들지 않는다. 정책 화면에는 계좌별 스위치·한도·계좌 상세 링크만 두고 주문 다리는 해당 파생 계좌 안으로 옮긴다.
- 계좌 상세는 자산·보유·위험을 먼저, 주문·체결은 그다음에 둔다. 세금·매수 이력·전문 지표는 접어 보여 주며 시장 변경으로 다른 시장의 값이 남지 않게 한다.
- 고급 성과는 보정·기준선 비교·강화학습 분석을 설명 있는 펼쳐보기로 구성한다. 파생 성적표는 기본 성과 안에서 관련 계좌에 한해 접근한다.
- 보유 종목에서 시장·종목·거래소를 보존하여 차트·뉴스·판단 근거로 이동한다. 종목 검색은 시장 데이터 상단에 놓고 시장 개요·거래 순위와 구분한다.
- 자동 작업은 실행 중·대기·실패를 먼저 보여 준다. 수동 실행은 접고, 확인창에서 대상과 주문·AI 영향 및 요청 등록 후 실제 실행 여부를 설명한다. 모르는 영향은 확정해서 표시하지 않는다.
- 공통 오류 화면에는 다시 조회와 적절한 연결·수집 안내를 제공한다. 빈 기록과 조회 실패를 구분하고 기존 인증·확인 절차를 유지한다.

운영 서비스 시작·재시작, 실제 정책/계좌 모드 변경, 실제 주문·유료 AI 호출은 수행하지 않는다. 새 의존성·셸 스크립트·원장 변경은 없다. 실제 계좌 식별자나 원문 수집자료를 fixture에 넣지 않는다.

검증: 동작별 RED→GREEN, 전체 웹 typecheck/Vitest/build, 관련 Python 검사와 생성 메뉴 검사, 독립 코드 검토, 별도 합성 브라우저의 모바일·데스크톱·두 테마 및 핵심 이동·복구 흐름. CI 성공 뒤 일반 UI PR은 승인된 범위에서 머지한다.
