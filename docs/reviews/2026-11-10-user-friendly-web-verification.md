# 사용자 중심 웹 개편 검증

## 구현 범위

- 목적별 다섯 주 메뉴와 운영 하위 메뉴, 이동한 절의 기존 주소 호환.
- 오늘 화면의 현물 매수 정책·제한 사유·문제와 해결 링크, 일반 종목과 방어용 헤지 분리, 판단 필터·검색·쪽 이동.
- 시장별 자동/수동 제한적 매수/방어 정책, 사유·시장 현지 만료·이력·모든 실전 현물 계좌 확인.
- AI 원본·정량 국면·실효 정책 분리, 분석 입력·집행·승인 재검사 일치.
- 단타·파생 조작을 정책 화면으로 이동, 데이터 수집과 연결 설정을 같은 페이지에 배치, 긴 기록 접기.
- 모의·실전과 통화별 계좌 합계 분리, 일시정지 문구를 실제 중지·청산 계약에 맞춤.
- 양 테마 글자·대비·콘텐츠 폭·카드·표·여백·44px 조작, 작은 화면 확인창 스크롤과 포커스 보완.

## 독립 검토와 수정

Standards와 Spec 두 축의 별도 검토를 수행했다. 다음 문제를 RED 테스트로 확인하고 수정한 뒤 재검토에서 추가 P1/P2가 없음을 확인했다.

1. 수동 RISK_ON에서 기존 노출이 2종목을 넘을 때 최초 검사와 승인 검사의 불일치: 양쪽에서 신규·추가 매수 차단. AUTO에서는 기존 종목 ADD 허용 계약을 보존.
2. 수동 정책 만료가 DB 지문을 바꾸지 않아 열린 화면이 갱신되지 않는 문제: 서버 보정 시각의 만료 타이머·화면 복귀 재조회·오류 시 지난 실효 상태 숨김.
3. 이동한 수집 절의 북마크 단절: 기존 pathname/hash를 현재 페이지로 이동하고 검색 조건을 유지.

작은 설정 비중의 표시 반올림도 검증했다: `0.1 → 10%`, `0.0075 → 0.75%`, `0.0025 → 0.25%`.

## 실제 브라우저 확인

사용자가 macOS 잠금을 해제한 뒤 Chrome에서 합성 자료만 사용하는 별도 웹 검증 서버로 확인했다. 실제 브로커·운영 계좌·AI 호출과 연결하지 않았다.

- 375×812, 768, 1024, 1440px 반응형 화면과 라이트·다크 테마를 확인했다. 모바일 하단 메뉴와 계좌 화면의 모의·실전/원화·달러 분리도 확인했다.
- 정책 선택만으로 저장되지 않음, 사유 미입력 시 저장 비활성화, 토큰 누락 안내와 로컬 토큰 받기, 수동 제한적 매수 저장(10%·2종목), AI 원본 보존, 자동 정책 복귀와 변경 이력을 확인했다. 모든 쓰기는 합성 SQLite에만 수행했다.
- 시각 검사에서 발견한 1024px 상태바 겹침, 모바일 더보기 줄바꿈, 차단/확인 불가 정책의 오해 가능한 한도 표시를 수정했다. HOLD의 blocked는 원본 상태를 유지하고 화면에서 “주문 없음”으로 설명한다. 추가 회귀 테스트 4개에서 RED를 확인한 뒤 수정했고, 전체 웹 573개가 통과했다.
- 추가 변경도 독립 검토에서 신규 P1/P2가 없음을 확인했다. 최종 CSS는 반응형 테스트와 빌드 후 다시 화면으로 확인했다.

합성 서버의 일부 부가 조회는 fixture가 없어 404를 반환한다. 실제 운영 서버와 설치판의 검증을 대신하지 않는다.

운영 앱 재시작·설치판 교체·계좌 모드 변경·실주문·유료 AI 세션은 수행하지 않았다. 주문 허용 경로를 포함하므로 머지는 변경 요약 후 사용자 확인 대상이다.
