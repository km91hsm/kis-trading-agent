기준 `43b013fadd47b6a9ca5d3a2cd0c2d1b933818f2e`, 브랜치 `feat/m13-operational-clarity`.

## 반영 내용

- 설정 변경 인증의 명칭·설정 경로·로컬/원격 주소별 저장을 안내한다. 인증키 저장은 서버 인증 성공과 구분하고 401과 403 사유를 분리한다. 계좌 모드·일시정지·파생/단타·리스크 정책·수동 실행·감시목록 저장 전에 인증 필요 여부를 표시한다. 기존 서버 인증·실전 확인·API 본문은 유지한다.
- 다른 탭의 동일 주소 인증키 저장·제거·clear도 버튼에 반영하며, 다른 저장소·키 이벤트는 무시한다.
- 리스크 ON/OFF에 한글 설명과 일반 현물 적용 범위·종목당 최대 10%/최대 2종목·더 작은 기존 한도·단타/파생 별도 제어를 명시한다. 실제 위험 허용 규칙은 바꾸지 않는다.
- 원장의 상태를 바꾸지 않고 조회 시 중단·확인 필요·후속 정상 실행을 분류한다. 동일 전체 인자 범위 및 실패 종료 뒤 시작해 완료된 성공만 연결한다. 범위가 부족한 기존 실행 기록은 확인 필요로 남으며, 다른 시장·종목·계좌·skipped·병행 실행을 해결 근거로 삼지 않는다. 후속 정상 실행도 근본 원인 해결을 보장하지 않는다.
- 진행 중 실행 기록과 요청 큐를 별도로 보여 준다. 예약 작업과 하위 분석/요청은 중첩될 수 있어 개수를 합산하지 않는다. 원본 오류·CSV 이력을 보존한다.

## AI 실패 조사

유효 근거 ID 뒤 공백 설명을 보정하는 기존 #61과 Codex 실패 시 Claude 대체 1회(#65), 필수 토론 미완료의 동일 잡 재실행 1회(#70)는 이미 구현돼 있었고 관련 회귀가 통과했다. 교체 전 앱 코드에도 이 동작이 포함돼 있었다.

관측된 닫는 스마트따옴표 `”`는 기존 근거 ID 정규화 경계에서 빠져 있었다. 합성 단위/교차 토론 재현을 실패시킨 뒤 경계 하나를 추가했다. 알 수 없는 ID·비슷한 접두사 ID 거부는 유지한다.

과거 `ValueError`의 실제 원인은 기록만으로 확정할 수 없다. 향후 실패에는 실행 준비·실행·출력 읽기·스키마·정규화·토론 규칙·사용량·성공 기록의 경계와 예외형을 남긴다. 검증기가 반환한 모델 원문도 Codex 원장에 저장하지 않는다. 실제 AI 호출이나 재시도 확대는 하지 않았다.

동적 source_id schema enum은 현재 고정 정책/schema 해시와 진행 연구의 참여 증명 호환 설계가 필요해 도입하지 않았다.

- 주요 동작과 추가 경계는 합성 입력 RED→GREEN으로 검증했다. 원장/모델 외부 원문을 fixture로 추가하지 않았다.
- 최종 웹: typecheck, **60파일 640개 테스트**, build 통과. 기존 큰 청크 경고는 유지된다.
- 전체 Ruff, nav/SSE 생성 파일 검사, diff 공백 검사 통과.
- 작업 관련 Python 63개, 세션 관련 Python 141개, 메뉴 Python 8개 focused 검사 통과. 전체 Python 검사는 PR 준비 중 실행 중이며 최종 종료 결과는 PR 검증 기록을 따른다.
- 전체 diff를 요구사항/규칙 두 축으로 독립 검토했다. 같은 주소의 다른 탭 인증키 변경 시 버튼 미갱신 P2를 재현한 뒤 수정했고, 증분 재검토에서 두 축 모두 추가 P1/P2가 없었다.
