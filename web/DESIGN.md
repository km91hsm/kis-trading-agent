# 디자인 체계 (M11b · M13 다듬기)

개인용 자동매매 운영 대시보드 — 휴대폰·PC 겸용, 한국어, 표가 많은 고밀도 화면.
ui-ux-pro-max 조사(design-system · color · ux)에서 고른 방향 위에 M13 에서 design-taste-frontend 앱 화면 규칙(`data-terminal` 스타일, 그라데이션·글로우·아이콘 타일 없음)으로 밀도와 팔레트를 다듬었다. 값은 `src/styles/tokens.css` 가 원본.

## 방향
- 스타일: 차분한 중립 바탕 + 의미색만 채색. 장식·그라데이션·글로우 없음. 카드는 큰 반지름(14px)·얇은 선, 칩은 테두리 없는 알약(색은 바탕 틴트).
- 테마: 라이트·다크 둘 다 1급. 기본은 OS 설정, 토글로 고정(`localStorage` 키 `trader.theme`, `<html data-theme>`).
- 글꼴: Pretendard(조사 추천 Fira 는 한글 미지원이라 대체). 숫자는 `.num`(`tabular-nums`, 줄바꿈 없음). 코드·ID 는 `--font-mono`.
- 글자 스케일(운영 대시보드 밀도): `--text-xs` 12(표 머리·칩·라벨) · `--text-sm` 13(보조·표 본문·메뉴 하위) · `--text-md` 14(본문·섹션 제목) · `--text-lg` 16(브랜드) · `--text-xl` 20(화면 제목) · `--text-kpi` 22(합계·성과 큰 숫자). 줄 1.5.
- 글꼴 로딩: `pretendardvariable-dynamic-subset.css`(가변 1벌, unicode-range 조각 woff2 — 쓰는 범위만 받음, 빌드 용량 축소).
- 아이콘: 인라인 SVG 만. 이모지 아이콘 금지.
- 줄바꿈: `body` 에 `word-break: keep-all` + `overflow-wrap: anywhere` — 한국어는 어절 단위로 꺾고(「접/수」 방지) 긴 영문 id 만 강제로 자른다.
- 맨 폼 컨트롤: 클래스 없는 `input`·`select`·`textarea` 는 `base.css` 의 `:where()` 기본(높이 `--touch`, 테두리 `--fg-muted`, 바탕 `--bg-elev`), 클래스 없는 `button` 바탕은 투명 — 브라우저 기본 회색(다크에서 대비 2:1)을 쓰지 않는다. 특이도 0 이라 부품·화면 규칙이 이긴다.

| `--ok` / `--warn` / `--fail` | #1E6B3A / #8A4B0F / #B42323 | 6.1 / 6.4 / 6.2 | #5FD38A / #F2C14E / #FF7A7A | 10.0 / 11.2 / 7.4 | 상태 3단계 |

- 상태 칩 바탕 `--ok-bg`·`--warn-bg`·`--fail-bg` 위 글자 대비: 라이트 5.7/5.9/5.4, 다크 6.5/6.5/5.3. 칩은 테두리가 없으므로 이 대비가 전부다.
- 색만으로 뜻을 전하지 않는다: 상태·등락에는 글자(정상/주의/실패, ▲▼ 또는 +/−)를 함께 쓴다.
- hex 는 `tokens.css` 에만. 컴포넌트·base.css 는 변수만.
- 컨트롤 테두리(입력·버튼)는 `--fg-muted` 또는 전용 테두리 토큰을 쓴다. `--line`(라이트 `--bg` 위 약 1.4:1)은 WCAG 1.4.11 의 3:1 미달이라 구분선 전용.
- 예외: `index.html` 의 `theme-color` 두 값(#F7F8FA/#0F1217)은 `--bg` 라이트/다크를 그대로 옮긴 것 — 함께 바꾼다.

## 간격·모양·모션
- 간격 4px 격자: `--space-1/2/3/4/6/8` = 4/8/12/16/24/32px.
- 반지름 셋: `--radius` 8px(컨트롤·입력·빈 상태·차트 자리), `--radius-card` 14px(카드·행 카드·대화상자·합계 띠), `--radius-chip` 999px(칩·배지·사용률 칩). 그림자 `--shadow` 1단계(떠 있는 메뉴·시트에만).
- 모션 `--motion` 150ms, 전환은 색·투명도 위주. `prefers-reduced-motion: reduce` 면 전환·애니메이션 제거(base.css).
- 터치 대상 `--touch`: <1024 44px, ≥1024(마우스) 36px — 컨트롤 높이가 같이 줄어 밀도가 오른다. 상단 띠 높이는 `--bar` 44px 고정(메뉴 sticky·앵커 `scroll-margin` 이 이 값을 쓴다). 포커스 링 `:focus-visible` 2px `--focus` 항상 유지.
- 빈 상태(`Empty`)는 한 줄 약 38px(점선 테두리) — 빈 칸이 화면을 차지하지 않는다. 자료 없는 차트는 `Chart` 가 축 대신 같은 높이의 `.chart-empty` 자리만 남긴다.
- 겹침: `--z-sticky` 10(고정 머리줄), `--z-overlay` 100(시트·대화상자).

## 반응형·표
- 확인 폭: 375 · 768 · 1024 · 1440px. 모바일 우선.
- 넓은 표는 좁은 폭에서 행을 카드로 바꾸거나 가로 스크롤 래퍼에 담는다(표가 화면을 밀어내지 않게).
- 열은 숨기지 않는다. 화면 고유 표(지표·호가)는 좁은 폭에서도 `.table-scroll` 가로 스크롤로 남기고, 전역(`html`·`body`·본문)에 `overflow-x: hidden` 을 두지 않는다(`screens/__tests__/responsive.test.tsx` 가 고정).
- 상단 상태 띠: 상태 점·첫 사유·「N분 전 갱신」(`/system#health` 링크) · 지수·환율 칩(`IndexChips`, 장중만·`next_poll_ms` 폴링) · 사용률 칩 · 시계 · 테마 토글(「테마: 시스템/라이트/다크」 — 메뉴 「시스템」과 헷갈리지 않게 접두어를 붙인다). <1024: 첫 줄 건강 요약 + 테마 토글, 다음 줄 칩·시계. <768: 한 줄(상태 · 더 보기 ▾ · 시각 · 테마) — 지수·사용률 칩은 `details.statusbar-more` 안, 날짜·장 세션 글자는 숨긴다(`title` 로 남김). 좌우 가장자리 16px(본문과 같음).
- 공통 부품(`components/`, 스타일 `components.css`): 표는 `Table`(≥1024px `<table>` · 미만 `RowCard`, `useWide`), 쓰기 확인은 `Confirm`, 잡 실행은 `RunJobButton`, 라벨-값 격자는 `Stats`(`<dl class="stats" data-cols=auto|2|3|4 data-size=sm|kpi>`, <768 은 3·4열도 2열). 「값 · 값 · 값」 문자열 나열·`<dl>` 손제작·`<pre>` 덤프 대신 `Table`/`Stats` 를 쓴다. 시각은 `fmtWhen`(오늘 `HH:MM`, 다른 날 `MM.DD HH:MM`, 날짜만 `MM.DD`), 비율 필드(`*_pct` 가 0~1)는 `fmtPct`, 상태·국면·레인·환경 라벨은 `glossary` 로 통일한다. 행 카드의 제목 줄은 `long` 열 — 이름이 있는 표(계좌)는 그 열에 `long: true` 를 준다. 행 카드의 나머지 열은 2열 정의 목록(`.row-card-fields`, 값은 줄바꿈)이고, 버튼 열은 `action: true` 로 표시해 자기 줄(`.row-card-actions`)에 둔다 — 가로 스크롤 칩 줄로 값·버튼이 잘리지 않게.
- 성과 가독성: 개요 h2 「수익률·위험」, KPI 는 `Stats size=kpi`(수익률·최대 낙폭(MDD)·Sortino·회전율·토론 수렴율 — 값이 없으면 「—」 아래 「산출 자료 부족」), 판정 분포 줄은 값이 있을 때만; 계좌 비교는 빈 행 비고 「기록 없음」, 전부 비면 표 대신 「N일 기록 없음」; 섀도 기준선이 전부 표본 부족이면 표 대신 한 줄 「기준선 n개 · 표본 x/20 — 20쌍부터 집계」; RL 은 카드 2장(`.perf-cards`) 안 `Stats`(모델 버전·백엔드·스텝·저장일 + 승격 칩 / 섀도 집계 제안·적용·만기·평균 비중 LLM / RL·실현 합 RL / LLM); 파생 성적표 `Stats size=kpi` 4칸. 복기: 종목 코드+이름(백엔드 `name`), 층 한글(glossary `tier.*`), 「중요도(0~1)」, `?ticker=` 로 들어오면 그걸로 시작(결정 상세 「복기 메모리 보기」 → `/performance/memory?ticker=`). `Chart` 는 점 1개면 벤치마크가 있어도 빈 틀, 가격축은 `fmtAxis`(백만 이상 「1,235만」, 억 이상 「1.5억」).
- 성과·데이터도 페이지로(`gen.py PERFORMANCE_PAGES`·`DATA_PAGES`, 라우터는 `NAV.<screen>.pages` 를 그대로 경로로): 성과 3개 — 성과 `/performance`(개요·계좌 비교) · 복기 `/performance/memory` · 추가 분석 `/performance/analysis`(보정·섀도 기준선·RL·파생 성적표, fo 계좌 없으면 hidden) — 데이터 4개(하위 메뉴마다 한 페이지) — 시세·차트 `/data` · 뉴스·공시 `/data/news` · 테마·감시목록 `/data/themes`(테마·감시목록 두 절) · 지표·모델 `/data/features`. 페이지에 없는 절의 자원은 부르지 않는다(`useResource enabled`). 왼쪽 메뉴(≥1280)는 페이지 링크, 좁으면 `PageTabs`. 절 앵커 하위 목차는 페이지가 하나뿐인 화면(계좌·보유)과 상세 화면에만 남는다.
- 데이터 가독성: 시장은 화면 머리 세그먼트 「KR | US」 하나(`useMarket`, `?market=`, 바꾸면 페이지 param 초기화)로 고르고 절마다 select 를 두지 않는다. 뉴스·공시·지표 표는 30행 `Pager`(뉴스 `?page`, 같은 페이지의 공시는 `?epage`), 종목·꼬리표 열은 값이 하나라도 있을 때만, 출처·중요도·지표 열 이름은 `data.ts` 라벨 표(`sourceLabel`·`severityChip`·`featureLabel`, 모르는 값은 원문)로 한글, 시각은 `fmtWhen`·공시는 날짜만. 수동 입력은 접힌 `details`, 저장·감시목록 저장은 `Confirm`(본문에 저장할 내용) 뒤 쓰기. 감시목록에 새로 더한 종목은 저장 전까지 `data-draft` 노란 칩. 호가 숫자는 `fmtInt`, 검색 안내는 「종목명 또는 코드로 검색」.
- 데이터 드릴다운: 차트는 「일봉 | 1분」 세그먼트(`/charts/minute?count=120`, epoch 캔들·그날 체결 표식, `Chart intraday` 가 시간축에 시각을 보임, 비면 「오늘 분봉 없음」). 뉴스 종목 칩은 버튼 — 누르면 `?ticker=` 로 그 종목만 다시 읽고 필터 줄에 「차트 보기」(`/data?ticker=`, ChartView 가 그 코드로 검색해 바로 엶)·「해제」. 시장을 바꾸면 `ticker` 필터도 지운다. 모델 표·RL 실험 표는 `Table expand` 로 행을 펼쳐 상세(`/ml/models/{version}`·`/analytics/rl/experiments/{version}`)를 Stats + 표(중요도 상위 10 / 정책별 요약)로. RL 절에 섀도 거래 표(`/analytics/rl/shadow?days=30`, 30행 `?spage`).
- 결정 상세: 머리 제목은 코드+이름(백엔드 detail 이 `name` 을 실음). 라운드·토론 턴(details 안)·리스크 게이트(spot)/체크(fo)·이어진 주문은 `Table`(판단·측·결과·상태는 칩, 손절·가격·수량은 `fmtInt`, 주문번호는 `<code>`, 타이밍은 `timingLabel`). 근거 전문·에이전트 보고는 산문 유지(신호만 칩). 계좌별 「결과」 표는 게이트·주문 표와 같은 내용이라 없앴고 `/outcomes` 는 부르지 않는다. `lib/trace.ts` 의 `gateLine/orderLine/checkLine` 은 `traceSteps`(오늘 타임라인)가 쓰므로 남긴다.
- 내보내기·쓰기 확인: 계좌 상세 주문 표는 주문이 있을 때 `csvHref`(`/orders?date&account_id&format=csv`), 세금 로트 절(현물 계좌만, 연도 select 기본 올해·「전체」, 시장별 `[data-tax-market]` 블록에 요약 Stats + 실현 로트 표 + CSV `/accounts/{id}/tax-lots?market&year&format=csv`). 연결 키 저장은 `Confirm`(바뀌는 키 이름만, 값은 안 보임) 뒤 POST. 차트 시간축은 `fmtTick`(일봉 `MM/DD`, 분봉은 시장 시간대 `HH:MM` — `tz` prop, 기본 Asia/Seoul; 연·월 눈금은 기본 라벨).
- 오늘: 페이지 2개(`gen.py TODAY_PAGES`) — 현황(`/`)과 기록(`/log`: 주문·체결 → 다음 할 일 → 알림). 날짜는 `?date=` 로 두 페이지가 같이 쓴다(없으면 오늘을 따라감) — 왼쪽 메뉴의 페이지 링크(`Nav.pageTo`)와 `PageTabs` 둘 다 `?date=` 를 옮기고, 알림도 `/system/notices?date=`(KST 하루)로 그날만 읽는다. 페이지 탭은 `PageTabs`(시스템과 같은 부품). 현황에는 「아침 파이프라인」(시장 카드 2열 `.pipeline-grid`: 단계 칩 스캔·시장 세션·분석 n종목·결정 m, 발굴 줄, 종목 표 코드+이름·마지막 단계(glossary `stage.*`)·단계 수; 기록 없는 시장은 `Empty`)과 「리스크 게이트」(`/risk-checks` 표: 시각·계좌·종목(결정 링크)·통과/거부 칩·수량 조정·사유; 0건이면 hidden)가 있다. 파생 레인 카드는 `/fo/today` 로 아침 결정 한 줄(의도·방향·수단·확신, glossary `fo.intent.*`·`fo.dir.*`·`fo.vehicle.*`)·재평가 횟수·계좌 칩(손실 한도·진입 대기)을 덧붙인다(`FoLaneExtra`). 시스템 「파생」 절은 계좌 표 아래 계좌마다 주문 다리 표(`FoLegs`, `/fo/legs`: 다리·상태 칩 `leg.*`·수량 체결/주문·가격·시각). 현황 절 순서는 승인 → 「오늘 요약」 KPI(`.today-summary`, `Stats size=kpi`: 결정·주문·체결·실패·알림) → 레인 카드(`Stats cols=3`: 결정·주문·다음 예정 = 데몬 사용자 잡 `next_at`) → 결정(종목 코드+이름 · 내용 = 최종 의견 요약 = 백엔드 `summary`(rationale 첫 문장, `first_sentence`), 표의 long 열은 내용 칸 — 말줄임 + title; 응답 전엔 「불러오는 중」; 0건이면 CSV 숨김) → 주문·체결 → 다음 할 일(`Table`: 사용자 잡만 `USER_JOB_KINDS`, 한글 라벨 + 시장 칩 · 예정 「HH:MM · N시간 뒤」 · 마지막 칩) → 알림(`Table` 30행 `Pager`: 시각·종류(본문 「[제목]」 → 칩)·계좌·내용 첫 줄(원문은 title)·전송 실패 칩; 필터 칩은 한글). 기록은 맨 아래, 전체 폭, 2열 묶음은 없다. 계좌·보유: 합계는 `.kpi-strip` 한 카드 3칸(원화·달러·환율, 세로선 구분; 768~1023 2열+환율 전폭, <768 1열) — 칸 라벨에 범위 「모의 n · 실전 n」, 금액은 `moneyUnit`(「10,000,000원」·「$2,500.50」). 전역 버튼은 대상을 적는다(「전체 자동매매 일시정지/재개」). 계좌 목록은 `Table`(카드 격자 아님; 헤더 「순자산」, 승인 대기 0건은 칩 대신 흐린 「없음」, 현물 계좌가 없으면 「현물 계좌 없음」). 파생 계좌 카드는 `/fo/summary`(fo_nav_snapshot) 의 NAV·증거금(NAV 대비 %)·상태 칩(`FO_STATE_LABEL`)을 쓰고, 실패하면 `/accounts` 의 NAV·현금으로 물러난다. 계좌 상세(`/accounts/:id`)는 h1 「계좌 {id}」 → 머리 카드 `.account-head`(모의/실전·레인 칩, `Stats cols=2` NAV·현금(갱신 시각 sub), 모드 select·적용·`Confirm` 을 카드 안에 — 따로 「모드」 절은 없다) → 오늘 주문·체결(상태는 `statusLabel` 한글 칩: 체결 ok·실패/거절/취소 fail, 수량 `fmtInt`) → 보유 → 단타 → 리스크(`Stats cols=3` VaR·CVaR·베타 + 「한도 대비」 `Table`[항목·현재·한도(최대/최소/손실 N)·판정 칩 정상/초과/미달/자료 없음] — 막대 없음, 위험 기여만 막대, 자료 부족은 `Empty`) → NAV 추이(`Chart` 는 점 1개면 「자료 1일 — 추이는 내일부터」).

## 메뉴·앵커
- 화면 안 섹션 컨테이너는 `id={item.id}`(자동 생성 `generated/nav.ts` 의 id)를 단다 — 하위 목차가 `<path>#<id>` 로 스크롤하고 `IntersectionObserver` 로 현재 섹션을 표시한다.
- 화면에 페이지가 여럿이면(시스템: 상태 `/system` · 잡 `/system/jobs` · 기능 `/system/features` · 관리 `/system/admin`, `nav.ts` `pages`) 2단 메뉴는 절 앵커가 아니라 페이지 링크(`aria-current="page"`)이고, 왼쪽 메뉴가 없는 폭(<1280)은 화면 위 `.page-tabs` 알약이 같은 일을 한다. 절이 어느 페이지에 가는지는 항목의 `page`(`gen.py SYSTEM_PAGES`). 백엔드가 주는 `/system#절` 링크는 `lib/nav.ts resolveLink` 로 페이지 주소로 바꾼다. 메뉴 항목을 더 쪼개지 않는다 — 새 절은 기존 페이지 안에.
- 긴 목록(실행 기록·조작 이력, 이후 알림·뉴스·공시·지표)은 `usePaged`(30행, `?page=N`) + `Pager`(「‹ 1 2 3 ›  31–60 / 65」). 한 페이지면 Pager 는 없다. 한 화면에 표가 둘이면 param 을 따로 준다(잡 페이지: 실행 기록 `?page`, 요청 기록 `?rpage`). 날짜·종류 필터를 바꾸면 `usePageReset()` 으로 1쪽으로 돌아간다.
- 상세 화면(`/accounts/:id`·`/decisions/*`)은 생성 표에 없으므로 2단을 본문 DOM(`main section[id] > h2`, hidden 제외)으로 만들고 맨 위에 「‹ 돌아가기」(계좌 → `/accounts`, 결정 → `/`)를 둔다. 결정 상세는 오늘 메뉴를 현재로 표시한다(결정 절에서 들어옴).
- 하위 목차는 현재 화면 것만 펼친다. 화면이 섹션을 `hidden` 으로 숨기면(승인 0건·없는 레인·파생 계좌 없음) 목차에서도 빠진다(`Nav.tsx` 가 본문 DOM 을 MutationObserver 로 본다) — 죽은 앵커를 메뉴에 두지 않는다.
- 현재 항목은 방금 누른 항목(해시)이 우선이고, 사용자가 스크롤 입력(wheel·touchmove·방향키)을 하면 보이는 가장 위 섹션으로 넘어간다. 같은 항목을 다시 눌러도 스크롤한다(`location.key`).
- 왼쪽 메뉴(≥1280) 위에 브랜드 「trader」, 바닥에 「데몬 정상 · v0.2.0」 푸터(`/system/health`).


## 운영 가시성
- 구독 사용량은 Claude와 Codex 이름을 함께 표시한다. Codex 창은 공급자가 반환한 기간으로 구분하고 미제공·조회 실패·이전 관측을 명시한다. 이 프로그램의 오늘 호출·토큰·비용 집계와 구독 전체 사용률은 구분한다.
- 상태를 설명하는 회색 칩·배지는 neutral 전용 글자·배경·테두리 토큰을 쓴다. 보조 설명용 `fg-muted`를 상태 표식에 그대로 쓰지 않는다. 두 테마에서 글자뿐 아니라 표식 경계도 구분되어야 한다.
- 페이지 번호를 누르면 해당 표/목록의 시작에 스크롤과 포커스를 맞춘다. 처음 표시하거나 자료만 갱신될 때는 사용자의 위치를 유지한다.
- 잡 요청은 기본 진행 우선이며 대기는 우선순위·등록 순서, 종료는 종료시각 최신순이다. 최신 요청순과 상태 필터를 제공하고 화면 표시순이 실제 실행순을 바꾸지 않음을 안내한다.
- 쓰기 토큰은 브라우저에 한 개만 저장된다. 설정된 경우 입력을 접고 상태만 보이며 열기·숨기기를 제공한다. 저장 성공 뒤 접고 이전 인증 안내를 지우며 값을 화면이나 이벤트로 전달하지 않는다.
- 오늘 현황의 첫 절 「현재 운영 상태」는 `Stats` 4칸(시장 시간·새 분석 제한·수집 상태·토론 참여). 과거 날짜를 조회해도 현재 설정임을 표시한다. 정규장 예정 시간과 실제 휴장 확인을 구분한다.
- 데이터 시세·차트는 주요 매크로 → 거래대금·등락 순위 → 종목 차트 순서다. 매크로는 저장 관측일·원천·대체 지표를 값 곁에, 상세 출처와 미제공 사유는 접힌 표에 둔다. 실시간 시세로 표현하지 않는다.
- 거래대금은 `ranking`, `sort`, `activity_q`, `growth_only`, `apage`로 탐색 상태를 보존한다. 30행 `Pager`, 계산 불가 사유, 시장·거래소를 유지하는 종목 차트 링크를 제공한다. 첫 수집 대기·수집 꺼짐·장외·0건·최근 실패를 나누어 표시한다.
- 시스템 기능의 「데이터 수집」은 요청 시도·응답·유효 자료 성공·값 변화 시각을 구분한다. 과거 달력과 현재 수집 대상 미확정 항목은 별도로 표시하고 활성 대상 분모에 섞지 않는다.
- 결정 상세의 「분석 입력 내역」은 당시 snapshot·전달용 도구 응답 기록·근거 인용을 분리한다. 기록 없는 과거 전달을 현재 규칙으로 재구성했다면 명시하고 실제 모델 수신/활용을 단정하지 않는다. 쟁점 비교는 주장·상대 반론·재답변을 같은 쟁점 아래 보여 준다.
- 관리 설정에는 실제 리스크 수치와 다음 분석에 적용될 토론 참여 설정을 보여 준다. 첫 키보드 포커스는 「본문으로 바로가기」이며 main으로 포커스를 이동한다.
